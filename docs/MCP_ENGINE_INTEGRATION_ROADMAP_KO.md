## 반드시 구축해야 하는 제작 시스템 (우선순위)

### P0 — 신뢰할 수 있는 모델 상태와 편집 권한

1. 실시간 Creator 브리지가 **정점, 삼각형, UV, 키폼 바인딩 값, 정확한 node transform, 렌더 마스크, 물리·드라이버 관계**를 읽을 수 있게 확장.
2. 파츠 GUID ↔ 실행 중 Creator UUID를 명시적으로 대조하고, 편집 전에 소스 SHA·scene revision·부모 계층·메시 fingerprint·파라미터 GUID·key index를 확인. **이름만으로 대상 선택 금지.**
3. 매 수정에 `request_id`, `model_revision`, `expected_before`를 요구하여 중복 요청을 재시도할 수 있게 하고, 변경된 상태에는 충돌을 반환.
4. Creator UI 스레드에서 단일 트랜잭션으로 모든 변경 적용. 실패·불일치·중단 시 전체 복원. Undo/Redo와 저장 파일이 동일한 상태여야 함.
5. 모델 백업, 출력 경로 보호, 샌드박스/허용 경로, 임의 코드 실행 비활성화, 토큰 보호. MCP 연결 자체와 Creator 연결은 별도 증명.

### P1 — 완전한 리깅 편집 명령 집합

- **메시:** 투명 알파 윤곽, 구멍, 사용자 지정 경계, 자동 삼각분할, 메시 수동 이동/리토폴로지, UV/원화 픽셀 간 대응, 기존 키폼 보존/재매핑.
- **계층·기준점:** 부모/자식, Z 정렬, 메쉬 그룹·워프, 회전 원점, 관절 중심, 부착점, seam, occlusion anchor, `lockToRoot`를 구분. 피벗 이동은 자식·변형·물리 보정 없으면 거부.
- **파라미터·키폼:** 축, 디폴트, 범위, 키 간 보간, 연결 바인딩과 물리 드라이버, 중립/극단/중간 자세, 1D·2D 및 조합, 빈 키폼만 채우거나 명시적 버전 관리.
- **2D 표현:** 얼굴 3×3 이상 회전/관계 가중치, 눈꺼풀, 흰자/홍채/하이라이트, 입술·입안·혀·치아의 독립 모션, 상체 관절/팔/손, 가림 복원.
- **물리·특수:** 머리·귀걸이·망토·소매의 독립 흔들림, 모션 중 관성, 클리핑·복합 합성, 발광/노멀 텍스처, TTS 립싱크 파라미터 매핑.
- **원화:** 파츠별 캔버스/크롭 오프셋/픽셀 해시/투명 경계, 숨겨진 관절·머리카락 복원; 원화 추정물을 원본으로 주장하지 않기.

### P2 — 고품질 자동 제작과 검증

1. 공식 Inochi Creator AutoMesh 결과를 동일 자산의 기준선으로 저장.
2. AI/기하 알고리즘이 메시·키폼·물리를 후보별로 생성; 수량이나 계산량에 인위적 상한을 두지 않되 렌더 엔진 실제 지원 한계는 기록.
3. Creator/SDK와 동일한 evaluator로 중립, 9방향, 동작 극단, 혼합 표정, 입모음, 팔 자세, 물리 시간 경과를 실제 렌더링. **샘플 좌표의 삼각형 검사만으로 성공 판정 금지.**
4. 반전, 접힘, 마스크 관통, UV 찌그러짐, 원화 정체성, 좌우 연속성, 경계 균열을 수치와 시각 기준으로 비교.
5. AI가 실패 부위만 수정하고 다시 렌더·검사. 품질 저하 시 원본 상태 복원; 실패 로그/인증된 포즈 결과 보존.
6. 공식 Creator에서 수정 가능한 최종 파일 저장 및 다른 기기/런타임에서 동일 파라미터 평가; 그 뒤 방송용 AIRI 통합 테스트.

## 이번에 실구현한 좁지만 중요한 부분

- `rig_manual_handoff` / `inochi-rig manual-handoff`: 특정 노드의 **정확한 GUID·부모·자식·raw transform·mesh SHA·정점/삼각형/UV 수·파라미터 GUID·바인딩 인덱스·키폼 축·isSet 셀·마스크/텍스처 필드** 조회. 별도의 유효한 기준점 manifest를 주면 랜드마크/실제 노드 원점을 구분한 플래너 좌표를 함께 제공. 미지원 월드 좌표는 `UNSUPPORTED`로 보고함.
- `rig_binding_vertex_slice` / `inochi-rig binding-slice`: 실제 저장된 원본 정점·UV·변형 오프셋을 GUID + 바인딩 인덱스 + `[x,y]` 키 + 정점 구간으로 한정해 조회. 긴 모델도 페이지 단위로 수신할 수 있음.
- 예외: 위 기능은 **파일 상태만 관찰**하며 실행 중 Creator의 상태를 원자적으로 비교하거나 시각적 완성도를 판단하지 않음.

## 병합/라이선스 원칙

- psd2live 저장소 최상위 LICENSE는 GPL 계열이므로 구현 코드를 MIT 프로젝트에 무검토 복사하지 말 것. 필요한 경우 원본 라이선스 의무에 맞춰 **별도 프로세스 연동** 또는 독립 재구현을 선택.
- 각 프로젝트의 도구 이름/설명은 API 참조 자료일 뿐 동일 구현으로 취급하지 말 것. 자체 기능으로 이식한 것이 없으면 `not integrated`로 유지.
- 전문 리거 수준 이상의 품질은 **동일 원화·동일 파라미터에서 공식 Creator 기준선과 실제 렌더링 비교를 통과**해야만 주장 가능.
